## Description
Add "review" to schema.STATUSES, between "in_progress" and "blocked", so a ticket can sit awaiting review as a first-class state rather than being faked with a tag or a note.

Touches:
- src/arbite/schema.py: STATUSES; anything that validates or orders a status.
- src/arbite/sinks/sqlite.py: any status CHECK constraint or enum-ish column handling, plus a schema version bump if the sink guards one.
- src/arbite/cli.py: every --status choice list and status filter help.
- src/arbite/query.py: status ordering, so listings put review where it belongs.

This is the foundation ticket for the review workflow: the review/ folder, submit and accept all depend on the status existing and validating first. No command should yet *set* the status here -- that arrives with set-status and submit.

Acceptance: a ticket with status review round-trips through both sinks, validates, and appears in arbite list --status review.
