## Description
Add a 'references' field to the ticket schema: a list of plan documents under the arbite root's plans/ bucket, stored root-relative (e.g. 'plans/review-workflow.md', which resolves to .arbite/plans/review-workflow.md). References are NOT repo-root paths.

Touches:
- src/arbite/schema.py: FIELD_ORDER (place it next to depends_on, which it most resembles), parse_ticket, to_markdown, to_dict, validate_field, coerce_field_value, SETTABLE_PROPERTIES. It is a comma-separated list property like tags/depends_on.
- src/arbite/sinks/sqlite.py: persist and return the list; schema version bump if guarded.
- src/arbite/cli.py: 'create --references' as a comma-separated flag.

The hard requirement is the one schema.py already states about itself: to_markdown() must reproduce the stored form byte-for-byte, and the file sink and sqlite sink must stay interchangeable. An empty references list must render exactly as it does today for an absent field -- do not introduce a stray 'references: []' line into every existing ticket.

Acceptance: round-trip tests pass for both sinks with references absent, empty, single and multiple; arbite show renders identically from either sink.
