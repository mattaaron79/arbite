## Description
Add 'arbite submit <id>' for an agent that has finished the work and is handing it off.

Behaviour depends on the project config's 'review' flag:
- review: true (the default) -- status becomes 'review', the ticket moves to review/, and the assignee is KEPT. A ticket in review is still owned by whoever did the work; they are who a reviewer sends it back to.
- review: false -- the ticket is closed exactly as 'arbite close' does, including dating 'closed'.

Both paths append an auto-note ('Submitted for review.' / 'Submitted; closed (review disabled).'), with an optional --message appended as detail, following the pattern release/shelve/unblock already use.

Use the same compare-and-swap discipline as claim: read, build the Expect, write, so two agents racing cannot both submit.

Refuse to submit a ticket that is already closed, and say so clearly.

Acceptance: with review enabled a submitted ticket is in review/ with its assignee intact and a note; with review disabled the same command closes it.
