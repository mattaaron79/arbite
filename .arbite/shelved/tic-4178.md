## Outcome and scope
Extend both-sink upgrades, export, migration and doctor to worker profiles, reservations, offers and packages. Keep immutable historical attribution and validate links and combined scheduling invariants.

## Acceptance criteria
- Quiescent transfers preserve the owner and worker distinction, continuity binding, completed history and offer states.
- Doctor detects dangling offers, overlapping reservation or package membership and inconsistent attempts without guessing reassignment.
- Active or pending work prevents an unsafe store switch, and removing a profile cannot erase historical actor references.
- Legacy ad-hoc stores need no mandatory registration and no central service.

## Validation
Full file and SQLite round trip with a partially completed package, deliberate integrity damage, legacy upgrade and active-transfer refusal.

## Boundaries and handoff
Implement this slice only: no daemon, agent launcher, automatic stale recovery, worktree workflow, central database, factory or dashboard. Preserve both-sink behaviour. The shared-directory proxy is available by this point in the epic, so use file claims while working this ticket rather than coordinating edits by hand. Record implementation decisions, validation results, observable behaviour and remaining limitations in ticket notes before close.
