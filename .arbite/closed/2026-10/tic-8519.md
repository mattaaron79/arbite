## Description
`create` prints `created tic-XXXX at <path>` and `raw` prints a longer capture line, and the docs state the text output is not a stable format -- so a caller that has just created a ticket has no safe way to learn its id. Add --json to both, printing the new ticket in exactly the shape `show --json` prints: one JSON object, no extra keys. See plans/milieu-cli-gaps.md.

The wrappers come free. bug/feature/request/memo/wish are not separate handlers: one loop in build_parser registers each subparser and ends with set_defaults(func=cmd_raw, type=<name>) (cli.py:4479-4491), so the shortcut is byte-for-byte the long form. Adding _json_flag inside that loop (next to _sink_flag at 4490) gives all five the flag; add _json_flag (cli.py:101-102) to p_raw before 4472 and to p_create before 4442.

Print the ticket object the handler already built, the way cmd_show does at cli.py:2701 -- Ticket.to_dict(sink.location(id)) (schema.py:304-317). Do NOT use cmd_claim's OperationResult envelope (_emit_result, cli.py:492-501): the contract is "same shape as show --json", and cmd_delete (cli.py:3175-3178) is the ticket-document precedent for a mutating command. Keep the payload free of extra keys even though derived keys are permitted elsewhere (cmd_fetch injects derived_note at 1393, _cmd_list_raw injects request at 1735). Capture `location` once: cmd_create already does (1298), cmd_raw calls sink.location inline in the f-string (1356-1361). Cover create's --blank template branch too (1299-1305). A raw-status ticket is printable today -- sink.get has no status filter (sinks/base.py:291-297, `raw` is in FLAT_STATUS_DIRS) -- so raw --json output round-trips through `show --json` with nothing special-cased.

Depends on the description ticket: once Ticket.to_dict carries `description`, create/raw --json inherit it, which is why this ticket is filed after it and not beside it.

Docs: the "Parse JSON, not tables" sentence in docs.py (1060-1065) hand-enumerates the --json commands and must gain create, raw and the five shortcuts, or it becomes the one stale claim about the surface. Optional: demo --json in the README Quick start (56-72). `arbite docs commands create|raw|bug|...` renders flags from the live parser (docs.py:1475).

Acceptance: `arbite create --title ... --type feature --tier low --domain io --json` prints one JSON object whose `id` is the new ticket; `arbite show <id> --json` prints the same payload. Same equality for `raw <type> ... --json` and for each of the five shortcuts. Exit 0, one document on stdout, nothing else on stdout. Both sinks: `path` differs by design (filesystem path vs `sqlite:<db>#<id>`, sinks/file.py:362 vs sinks/sqlite.py:384), so parametrize.

Tests: tests/test_cli.py beside test_create_requires_its_fields_unless_blank (699) and test_the_shortcuts_are_the_raw_command (752), using the `cli`/`project`/`ticket_id` fixtures (33-114) and the sink_kind parametrization (785). No existing scenario in interaction-examples.md runs create, raw or a wrapper, so nothing breaks; add two scenario ids (create --json, raw --json with one shortcut asserted as the long form's twin) under a new family prefix -- the existing families (WS/CL/LS/RD/.../ST) all cover the coordination slices and ticket CRUD has none -- asserted through tests/examples.py, which reads the transcript from the document and compares JSON blocks as parsed documents.
